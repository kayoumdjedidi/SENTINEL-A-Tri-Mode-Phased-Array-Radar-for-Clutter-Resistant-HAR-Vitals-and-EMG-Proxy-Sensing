SD card / Software Setup
In order for the Raspberry Pi to control the Phaser devices, you will need to write the ADI Kuiper Linux image to an SD card and configure it. The SD card that ships with the phaser kit MUST be updated with a new image. The Phaser software is tested with Kuiper Linux 2021_R2, which, in spite of the “2021” in the name, was released in Spring, 2023. While there are newer Kuiper Linux releases, this version is required to maintain compatibility with the current phaser software packages.

Download the image from:

2 April 2023 release (2021_r2)

Complete instructions for how to write it to the SD card and how to configure an example system are provided at Analog Devices Kuiper Linux.
Hints: The Kuiper Linux wiki pages give a few options, but the “official” Raspberry Pi imager is very straightforward:
Raspberry Pi Imager

Switch to ADI Kuiper Imager once it's stable and documented on the wiki.

After writing the image, if a window pops up saying “this card needs to be formatted, would you like to format it now?”, the answer is NO. Eject the card and insert it into the Raspberry Pi's SD card slot.

Configuring the SD Card
The easiest way to configure the SD card is by running a setup script. This does require a wired or wireless internet connection, but it is much easier than doing things manually. A wired connection is fairly straightforward if your network supports DHCP. If you need to use a wireless connection, you'll have to boot to the graphical desktop and connect manually.
Once connected to a network, run the following commands (and take a look at the setup script if you're suspicious, and note that there may be some updates as newer versions of Kuiper Linux are released.) The script is commented if you want a detailed description of what it's doing.

wget https://github.com/thorenscientific/rpi_setup_stuff/raw/main/phaser/phaser_sdcard_setup.sh
sudo chmod +x phaser_sdcard_setup.sh
./phaser_sdcard_setup.sh
sudo reboot
(Wait for the system to reboot)
Note: After running the script, the hostname will be phaser.local
If you are going to be running scripts and other software directly on the Raspberry Pi, it's a good idea set a few options using the Raspberry Pi configuration utility. This can be accessed from the Start Menu under Preferences, or by running:

sudo raspi-config
from the command line. Set the locale, keyboard, timezone, and wifi country (if you'll be connecting to your network by wifi.)

You'll also need to downgrade the numpy version to fix a compatibility issue with our existing example python scripts:

sudo pip install --force-reinstall numpy==1.22

Initial Calibration
The phaser board is initially uncalibrated; each element will have a slightly different gain and slight phase error due to numerous factors. The phaser_examples.py script provides a calibration utility that will generate calibration files. Shut down the GUI if it is running. Place the HB100 directly in front of the array at mechanical boresight , approximately 1.5 m away. Then run:

cd ~/pyadi-iio/examples/phaser
python phaser_examples.py cal
The script provides debug information and plots as it is running, you may have to close out of each plot for the script to proceed. After running this script, files gain_cal_val.pkl and phase_cal_val.pkl will be placed in the working directory. The GUI program will also load these files automatically when run again.

CN0566 Software
There are several pieces of software used with the CN0566 Phaser, including a user-friendly Graphical User Interface (GUI) and a number of command-line utilities. These are located in the pyadi-iio examples folder. Assuming the pyadi-iio repository has been cloned to user analog's home directory, the path to the cn0566 examples is:

analog@phaser:~/pyadi-iio/examples/cn0566 $
Configuration and Calibration files
There are several calibration and configuration files that the software uses. Calibration files are generated as described in CN0566 Calibration, and are as follows:

hb100_freq_val.pkl - Measured frequency of microwave source
gain_cal_val.pkl - Gain calibration coefficients
phase_cal_val.pkl - Phase calibration offsets
While these are intended to be generated once and re-used each time a program is run, they are easy to recreate as the physical surroundings change - microwave reflective surfaces, distance between the phaser array and source, changing between the onboard transmitter or independent microwave source, etc. If these files are deleted (or not present in the first place), default values will be used.

The config.py file contains parameters for the operation of the phaser, including signal frequencies, sample rates, bandwidths, etc. This file can be edited directly, after which any software using it must be restarted.
As a convenience for staying consistent with the Pyadi-iio Git repository, the config.py file can be copied to config_custom.py*. If present, software will use config_custom.py - this file can be edited without affecting the Git repository. ===== GUI operation ===== The GUI can be launched either from the command line or from the Thonny IDE. From the command line, run the following command: <code> python3 cn0566_gui.py </code> which will print debug information to the console as shown below. In this case, gain and phase calibration files were not present, but a frequency measurement file for an HB100 was found.

Why you see two sidebands, not a shifted 157 Hz line

The speaker cone oscillates about a fixed point (zero-mean velocity), so CW radar sees phase modulation, not a steady Doppler offset. That produces symmetric micro‑Doppler sidebands ±nf_audio around the carrier, while the carrier at 100 kHz stays put.(sound-au.com)
The Doppler shift magnitude is set by velocity, not the audio tone itself: (f_D = 2v/\lambda). A 1 mm peak displacement at 157 Hz gives (v_{pk}\approx1 m/s) → (f_D\approx67 Hz), so you’d expect first-order sidebands tens of hertz wide, not a 157 Hz IF line. Larger shifts need millimetre‑scale strokes and clean line‑of‑sight.
Because the cone displacement is a small fraction of the 3 cm wavelength, the phase modulation index is tiny, so first sidebands are ~20–30 dB below the strong Tx‑Rx leakage and static clutter, leaving the bright central line.
Why hand-waving “works” but the speaker doesn’t

A moving hand changes range by centimetres, giving larger (f_D) and higher modulation index → stronger sidebands that clear the leakage floor.
The cone may be partially shadowed by the grille/box; most energy you illuminate is still the stationary baffle, so clutter dominates.
Practical tweaks to make the speaker motion pop out

Increase RCS of the moving part: remove grille, tape a bit of foil on the cone dust cap, aim the array normal to its motion.
Suppress direct leakage/clutter: add absorber between Tx/Rx, separate antennas, or lower Tx gain on the unused channel; then digitally notch DC by subtracting a running average of the IQ before the FFT.
Look at phase, not just magnitude: form (z[n]=r[n]\cdot\text{conj}(tx[n])), unwrap phase, differentiate → audio-rate Doppler trace; or run a narrowband IQ high-pass (<30 Hz) to pull out the 157 Hz modulation.
Boost SNR: raise Rx gain (or move closer) until sidebands rise above –50 dBFS but avoid clipping.
If you need range gating, switch to the FMCW example and window on the range bin that contains the speaker to reject room clutter.
Natural next step: implement the simple clutter‑subtraction + phase‑demod path in CW_RADAR_Waterfall.py and re-run with the foil on the cone; the 157 Hz tone should appear as a clean audio line.

Here’s what the script is doing and what each plot/variable means:

Core signal flow

Pluto Tx generates a single complex tone at signal_freq (default 100 kHz) around an IF/LO of center_freq = 2.2 GHz. The Phaser LO (output_freq/4) upconverts that to ~10 GHz RF.
The scene reflection is received by the Phaser array, mixed to 2.2 GHz in Pluto Rx, and digitized at sample_rate = 0.6 MS/s.
In software we synthesize the same 100 kHz tone and feed Pluto Tx (iq), then read Rx in blocks of fft_size samples (1024*64).
For display:
FFT / waterfall use the raw Rx block.
Time + audio plots first mix the block down by exp(-j2π·signal_freq·n/fs) to baseband and decimate by bb_decim (6 → view_fs ≈100 kS/s) to make motion visible in time.
Key parameters

signal_freq: the CW baseband tone you transmit. Sets where the Doppler sidebands appear in FFT (at ±f_D around this tone). Keep it comfortably inside the 0.6 MS/s Nyquist band; 50–150 kHz is safe.
center_freq: Pluto LO (2.2 GHz). Combined with Phaser LO gives RF = (output_freq – center_freq) ≈ 10 GHz.
sample_rate: 0.6 MS/s. Higher gives wider Doppler span but heavier CPU; lower eases load but shrinks spectrum.
fft_size: 65536. Large for fine frequency resolution (~9 Hz bins at 0.6 MS/s).
bb_decim: 6. Decimation used only for time/audio plots; lower = more detail but more noise, higher = smoother but slower.
Gain taper: gain_list Blackman across 8 RX elements to reduce sidelobes.
GUI sliders: waterfall color scale (low/high dBFS).
What each plot shows

FFT (top-left): Magnitude spectrum of the current raw Rx block. The tall middle spike is Tx/Rx leakage + static clutter at 100 kHz; Doppler sidebands from motion appear symmetrically around it.
Waterfall (bottom-left): History of spectra. Stationary clutter stays as a horizontal yellow band; moving targets trace slanted lines.
Time trace (top-right): Baseband I/Q after mixing out 100 kHz and decimating. Should show a near-DC (slowly varying) complex signal; motion modulates its phase/amplitude.
Audio envelope (bottom-right): |I+jQ| after a ~8 Hz high-pass (40 ms smoother). This highlights faster variations (tremor, fan blades, speaker cone vibrato).
Choosing transmit frequency

Pick signal_freq away from DC to avoid DC offsets/1/f noise and away from the band edges to leave room for Doppler. 80–120 kHz is a good default at 0.6 MS/s. If you raise sample_rate, you can also raise signal_freq proportionally.
Why you can’t see < ~50 Hz Doppler right now

The audio plot intentionally high-passes at ~8 Hz; that part is fine for <50 Hz.
The real limit is SNR vs. leakage: very slow Doppler (tens of Hz) means very small frequency/phase deviation. If leakage/clutter dominates, the sidebands are buried. Mitigations: increase Rx gain, add absorber/antenna separation, or notch the carrier (subtract average IQ) before plotting.
If you truly need sub-10 Hz motion, lower signal_freq isn’t required; instead improve clutter suppression and maybe lower bb_decim to 1–2 and increase smoother taps so the time plot shows slow phase drift without being swamped by noise.
If you want finer slow-motion visibility

Set bb_decim = 2 and taps = int(0.2 * view_fs) (~200 ms) for deeper low-frequency envelope.
Add a running IQ mean subtraction before FFT/time plots to notch the carrier leakage.
Raise Rx gains slightly (e.g., 40 dB) if headroom remains.

You’re seeing the LO leaking. The Phaser generates LO ≈ 12.4 GHz and mixes it down to 10.2 GHz (LO – IF). Imperfect isolation means some LO energy escapes the VCO/PLL path and reaches the antenna—either directly through the on‑board RF switch network, the LO_OUT routing, or PCB/connector coupling. Typical mixer/PA isolation is only a few tens of dB, so with no band‑pass filter you’ll see both:

10.2 GHz: desired RF (LO – 2.2 GHz IF).
12.4 GHz: LO feedthrough/harmonic spur.
How to suppress the 12.4 GHz peak:

Put a 10–10.5 GHz band‑pass filter on the TX port (best fix).
Verify GPIO settings keep LO_OUT disabled (you can set gpio_vctrl_2 = 1 already; if available, ensure no LO_OUT path is selected).
Increase TX atten / lower drive to reduce absolute leakage level.
Separate TX/RX or aim the analyzer at the antenna through a band‑limited horn/waveguide.
If using OUT1 vs OUT2, try the other port—layout differences can change leakage a few dB.
The second peak is expected without output filtering; filtering or shielding is needed to make it disappear.
